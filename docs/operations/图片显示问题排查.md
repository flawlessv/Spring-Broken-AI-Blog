# 生产环境图片显示问题排查指南

## 🔍 问题诊断步骤

### 1. 检查图片文件是否存在

```bash
# SSH 登录服务器
cd /www/wwwroot/my-next-app

# 检查 public/images 目录
ls -la public/images/

# 检查具体文章的图片目录
ls -la public/images/posts/
```

### 2. 检查文件权限

```bash
# 确保 public 目录有正确的权限
chmod -R 755 public/
chown -R www:www public/  # 根据你的服务器用户调整
```

### 3. 检查 Nginx 配置

确保 Nginx 配置文件中包含静态文件服务配置：

```nginx
# 静态图片文件 - 直接由 Nginx 服务
location /images/ {
    alias /www/wwwroot/my-next-app/public/images/;
    expires 30d;
    add_header Cache-Control "public, immutable";
    access_log off;
}
```

### 4. 重新加载 Nginx 配置

```bash
# 测试 Nginx 配置
nginx -t

# 重新加载配置
nginx -s reload
# 或者
systemctl reload nginx
```

### 5. 检查 Next.js 应用

```bash
# 检查应用是否正常运行
pm2 status

# 查看应用日志
pm2 logs spring-broken-ai-blog --lines 50
```

### 6. 测试图片访问

```bash
# 直接访问图片 URL（替换为你的实际路径）
curl -I http://your-domain.com/images/avatar.jpg

# 或者通过浏览器访问
# http://your-domain.com/images/posts/article-slug/cover.jpg
```

## 🔧 常见问题及解决方案

### 问题 1: 图片文件不存在

**症状**: 404 错误

**解决方案**:

1. 确保部署时包含了 `public` 目录
2. 检查部署脚本是否正确上传了所有文件
3. 手动上传缺失的图片文件

### 问题 2: 权限问题

**症状**: 403 Forbidden 错误

**解决方案**:

```bash
cd /www/wwwroot/my-next-app
chmod -R 755 public/
chown -R www:www public/  # 根据实际情况调整用户
```

### 问题 3: Nginx 配置问题

**症状**: 图片请求被代理到 Next.js，但 Next.js 无法服务

**解决方案**:

1. 更新 Nginx 配置文件（参考上面的配置）
2. 重新加载 Nginx: `nginx -s reload`

### 问题 4: 路径问题

**症状**: 图片路径不正确

**解决方案**:

1. 检查图片 URL 是否正确（应该是 `/images/...`）
2. 确保图片存储在 `public/images/` 目录下
3. 检查 Next.js 的 `basePath` 配置

### 问题 5: 部署时图片未上传

**症状**: 本地有图片，但服务器上没有

**解决方案**:

1. 检查 `.gitignore` 是否忽略了 `public/images/` 目录
2. 确保部署脚本包含了 `public` 目录
3. 手动同步图片文件到服务器

## 📋 快速修复命令

```bash
# 1. 进入项目目录
cd /www/wwwroot/my-next-app

# 2. 检查图片目录
ls -la public/images/posts/

# 3. 修复权限
chmod -R 755 public/
chown -R www:www public/

# 4. 更新 Nginx 配置（如果使用）
# 编辑 Nginx 配置文件，添加 /images/ location 块
# 然后重新加载: nginx -s reload

# 5. 重启应用（如果需要）
pm2 restart spring-broken-ai-blog

# 6. 测试图片访问
curl -I http://your-domain.com/images/avatar.jpg
```

## 🔄 同步本地图片到服务器

如果本地有图片但服务器上没有：

```bash
# 方法 1: 使用 SCP（从本地执行）
scp -r public/images/ user@server:/www/wwwroot/my-next-app/public/

# 方法 2: 使用 rsync（从本地执行）
rsync -avz public/images/ user@server:/www/wwwroot/my-next-app/public/images/

# 方法 3: 通过 Git（如果图片已提交）
# 在服务器上执行
cd /www/wwwroot/my-next-app
git pull origin main
```

- [ ] Next.js 应用正常运行
- [ ] 可以通过浏览器直接访问图片 URL
- [ ] 图片路径在代码中正确（以 `/images/` 开头）

## 📞 如果问题仍然存在

1. 检查浏览器控制台的错误信息
2. 查看 Nginx 错误日志: `tail -f /www/wwwlogs/powder.icu.error.log`
3. 查看 Next.js 应用日志: `pm2 logs spring-broken-ai-blog`
4. 检查网络请求（浏览器开发者工具 → Network 标签）
