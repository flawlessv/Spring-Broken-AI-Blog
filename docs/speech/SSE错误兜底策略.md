# SSE 输出异常兜底（单一 QA）

## Q：如果大模型通过 SSE 返回的内容格式异常（比如 JSON 解析失败、Markdown 结构坏掉、HTML 标签没闭合），前端怎么兜底，才能保证页面不崩、用户还能继续用？

A：先说结论，目标不是“把坏格式修到完美”，而是三件事：

1. 页面不能崩。
2. 内容至少可读。
3. 用户还能继续聊、还能重试。

你提到的几个 case，先放最前面说清楚。

### 先看 3 个最常见 case

1. HTML 标签没闭合怎么办？
   浏览器的 HTML 解析器确实会“自动补救”，比如帮你补闭合标签，所以很多时候不会直接报错白屏。  
   但这个补救不等于“结果一定对”，最终 DOM 结构可能和预期不一致。  
   所以不要直接信任模型给的原始 HTML，建议默认当文本显示，或者先做白名单清洗再渲染。

2. Markdown 格式不完整怎么办？
   多数 Markdown 渲染器有容错能力，像未闭合列表、不标准标题、部分语法错误，通常还能渲染出可读结果。  
   但也有例外，比如复杂嵌套或代码块边界混乱，可能渲染异常。  
   所以要准备第二层兜底：Markdown 渲染失败时，自动切纯文本展示。

3. JSON 格式错误怎么办？
   和 HTML、Markdown 不同，JSON 没有“自动补救解析”，`JSON.parse` 失败就是失败。  
   这里必须 `try/catch`，失败后回退为原始文本或默认结构，不能让异常往外冒把会话打断。

### 一套可落地的兜底流程（按顺序执行）

1. 收流阶段：先拼完整，再解析。  
   SSE 是分段到达的，不要假设每次读到的都是完整事件。先把分段拼起来，再按事件边界切分。

2. 解析阶段：单条失败，不影响后续。  
   每条 `data` 都用 `try/catch`。这条解析失败就降级为文本继续走，后面的事件照常处理。

3. 展示阶段：优先可读，不追求一次到位。  
   先尝试正常 Markdown 渲染；如果报错，就自动降级纯文本。  
   目标是“用户能看到内容”，而不是“必须保持富文本样式完整”。

4. 结束阶段：把最后一段补上屏。  
   无论正常结束、报错结束还是用户中断，都先把缓存里最后那点内容补到界面，再改状态。  
   这样不会出现“最后几句丢了”的问题。

5. 交互阶段：给用户明确出口。  
   出现降级时要提示“已降级为纯文本”，并给“重试本轮”按钮。  
   局部消息失败只影响局部，不要让输入框和整个会话不可用。

### 你可以直接讲的实现要点

1. HTML：不直接裸渲染，先清洗或文本化。
2. Markdown：先渲染，失败自动降级纯文本。
3. JSON：`try/catch`，失败回退，不中断主流程。
4. SSE：支持半包和尾包，单条失败不中断整流。
5. 结束统一补尾：先把最后缓存内容写进 UI，再结束。

### 面试可直接说的版本（30 秒）

“这类问题我会按‘可用优先’处理。HTML 未闭合浏览器会有一定自动补救，但我不会直接信任原始 HTML；Markdown 渲染器有容错，但失败时要自动降级纯文本；JSON 解析失败必须 try/catch 回退。整个 SSE 流程里，单条坏数据不能中断整条会话，结束前还要把缓存里的最后内容补上屏，并给用户明确提示和重试入口。这样页面不会崩，内容也不会丢。”
